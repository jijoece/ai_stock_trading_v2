Treat ADR 0009 as authoritative. Present a concise implementation plan, then
implement it in the same session.

Required scope:

1. Create an isolated backtest_runtime/ distribution
- It must be installable independently with:
  pip install -e backtest_runtime/
- Pin lumibot==4.5.78 as a base dependency.
- Declare requires-python explicitly.
- Do not add LumiBot or a backtest extra to the root pyproject.toml.
- Do not install the root project, paper_runtime, and backtest_runtime together.
- Add a test asserting paper_runtime and backtest_runtime pin the same exact
  LumiBot version.

2. Enforce the credential-free entry point
Before importing LumiBot, the executable entry point must:

- scrub every credential-named variable identified by the pre-step evidence
  from os.environ;
- set LUMIBOT_DISABLE_DOTENV=1;
- redirect sys.stdout to sys.stderr.

The runtime must never accept, read, persist, or forward broker credentials.

3. Implement the bounded file contract
- Accept only caller-supplied historical bars and deterministic run parameters.
- Write results to a file rather than stdout or the paper-runtime JSONL protocol.
- Do not add a data fetcher, broker integration, scheduler, or paper_books access.
- Run with benchmark_asset=None and analyze_backtest=False.
- Validate input and output independently inside backtest_runtime.
- Reject unknown fields and malformed/non-finite values.
- Return normalized orders, fills, timestamps, prices, quantities, cash,
  positions, fees, realized/unrealized P&L, equity, drawdown, and final value.
- Do not serialize or expose LumiBot Python objects.

Use a versioned, framework-neutral JSON contract. Include canonical:

- schema version;
- historical-bar dataset checksum;
- run-configuration checksum;
- strategy/configuration identity.

The same input must produce a byte-identical normalized result document.

4. Preserve process and import isolation
- backtest_runtime/src may import only the standard library, pandas, and LumiBot.
- It must not import trading_research or trading_paper_runtime.
- The main project and paper_runtime must not import backtest_runtime.
- Do not modify execution authority, trading policy, paper accounting, or the
  existing backtesting engine.
- Add structural import-boundary tests for these rules.

5. Repair the existing LumiBot AST boundary
Move the tree-walking test out of the module guarded by
pytest.importorskip("lumibot"), so it executes in the normal main test
environment without LumiBot installed.

Do not add backtest_runtime as an allowed import location inside
src/trading_research; it is a separate top-level distribution.

6. Add backtest_runtime tests
Tests must not use importorskip. Cover:

- valid deterministic fixture execution;
- identical input produces byte-identical output;
- changed bar data changes the checksum and result;
- malformed or unknown input fails closed;
- inherited fake process credentials are scrubbed before import;
- sentinel .env and .env.local files are not loaded;
- exactly the documented benign LumiBot defaults resolve, with no additional
  credential-valued reads;
- broker and live data source remain None;
- zero outbound attempts under the fail-closed network guard;
- no benchmark or live historical-data access;
- stdout contamination cannot corrupt the result file;
- distribution and import isolation;
- matching LumiBot pins across the two isolated runtimes.

Reuse the verified pre-step guard logic where appropriate, but place maintained
runtime/test code in the correct package rather than importing executable
evidence scripts from docs.

7. Add blocking CI
Create backtest-runtime-tests that:

- uses the distribution’s declared Python floor;
- installs only backtest_runtime/;
- runs pip check;
- asserts lumibot==4.5.78;
- runs its complete test suite;
- enforces all five ADR 0009 credential-safety properties.

Keep the normal main-project jobs free of LumiBot.
